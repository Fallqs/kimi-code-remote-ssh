# 持久化 Bash

默认情况下，每次 `Bash` 工具调用都在全新的 Shell 中启动，调用之间不保留任何状态。持久化模式通过在每次命令执行前从持久化快照恢复 Shell 状态、并在命令成功后写回快照，使状态跨调用保留。本页介绍如何启用、哪些状态会保留，以及提交与回滚语义。

## 启用持久化模式

在 `config.toml` 的 `[bash]` 下把 `stateful` 设为 `true`（默认值为 `false`）：

```toml
[bash]
stateful = true
```

## 哪些状态会保留

启用后，每次命令仍会启动一个全新的 Shell 进程，但命令开始前会先从按 Agent 保存的快照中恢复其状态：环境变量（无论是否 export）、当前工作目录、Shell 函数定义、umask，以及已激活的环境（如 conda、venv）。典型用法是先执行一次 `conda activate myenv`，之后的每次调用都会运行在该环境中。别名、`set -o` 选项和 trap 不会保留。

这份状态在 Agent 的 `Bash` 调用与你手动输入的 `!` Shell 命令之间共享，只有一处不对称：Agent 调用总是从会话工作目录（或 `cwd` 参数指定的目录）开始，而你的 `!` 命令从被记住的工作目录开始。无论哪一侧提交的 `cd` 都会持久化，因此 `!` 命令会落在上一次已提交调用结束时的目录——方便你查看 Agent 刚刚操作过的目录。

快照保存在磁盘上，因此已提交的状态在 CLI 重启后依然有效，并会被下一条命令恢复。

## 提交语义

状态变更遵循提交语义：前台调用只有在以退出码 0 结束时才会把变更写回快照。以非零退出码结束、被终止或超时的调用会回滚——其中的 `cd`、`export` 等状态变更会被丢弃。后台 `Bash` 调用只读恢复快照，从不提交，因此不会改变已持久化的状态。`cwd` 参数设置单次调用的起始目录；该调用提交时，这个目录会成为持久化的工作目录，效果与一次成功的 `cd` 完全相同。

已提交的调用若改变了导出的环境，输出中会带有一行 `[bash state]` 提示，例如 `[bash state] conda=myenv; env: +MY_FLAG`。它只包含名称：激活的 conda 环境，以及新增（`+A`）、变更（`~B`）或移除（`-C`）的变量——绝不包含值，因为值可能含有密钥。工作目录的变化不会被报告；需要当前目录时运行 `pwd` 即可。

如果快照恢复失败（例如保存的工作目录已不存在），命令会从全新的 Shell 启动，并输出 `[bash state] replay failed (...)` 提示。
